`akm workflow run` and `akm workflow complete` now exit 75, not 2, when a
`RUN_LEASE_HELD` error refuses the command because another engine invocation
already holds the run's lease. `akm's state.db` contention (`STATE_DB_CONTENDED`)
exits 75 for the same reason. Both were previously `UsageError` (exit 2); they
are now a new `TransientError` class (sysexits `EX_TEMPFAIL`) so a scheduler or
cron wrapper can distinguish "retry shortly" from "fix the command line". The
JSON error envelope's `code` field (`RUN_LEASE_HELD` / `STATE_DB_CONTENDED`)
and message text are unchanged.

If a script or scheduled-task wrapper special-cases exit code 2 to detect a
held workflow run-lease or contended state.db, update it to check for exit
code 75 instead (or, more robustly, parse the JSON envelope's `code` field,
which this change does not touch).
