## #9544 — `akm index` embedding credential audit

A field report suspected `akm index` was sending embedding requests with no
`Authorization` header when `embedding.apiKey` was set to a `secret://`
reference, based on a gateway's request logs. Every path that builds an
embedding request — plain `akm index`, the CLI as a standalone process, an
`extends`-inherited `embedding.apiKey` with adapter detection persisting
mid-run, and `akm bundle update`'s post-commit embedding pass — was audited
and reproduced against a mock endpoint that records the `Authorization`
header of every request. None reproduced a keyless request: the credential
was already threaded through correctly on every path tested.

No action needed on upgrade. If you run an embedding gateway that enforces
auth (e.g. Bifrost) and still see unauthenticated requests from `akm index`
after upgrading, that is a genuine regression — please attach the exact
`embedding.apiKey` shape (`secret://…`, `$VAR`, or `${VAR}`) and whether the
run went through `akm index` directly or `akm bundle update` when filing a
new issue, since this audit's mock-server reproduction did not surface it.
