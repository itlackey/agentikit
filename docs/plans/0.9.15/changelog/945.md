### Added

- **Config `extends` inheritance and `akm config diff` (#945).** A config
  file can now set `extends: <path|bundle//conceptId>` to deep-merge a shared
  base config underneath it — local keys win — so a fleet of instances can
  keep one shared `engines`/`improve.strategies` block instead of hand-syncing
  it across hosts. The base resolves without the search index (a filesystem
  path relative to the declaring file, `~` expanding, or an already-synced
  bundle asset ref), runs through its own version and legacy-shape shims
  independently, and may itself set `extends` (chained; a cycle is a
  `ConfigError` naming the ref). `akm config get <key> --show-source` reports
  whether a value came from `local`, `extends:<ref>`, or `default`; `akm
  config diff <path|bundle//conceptId>` prints sorted `{ path, local, other }`
  rows for every leaf that differs between the effective config and another
  config file or bundle asset, redacting secrets on both sides first. Both
  are additive: `config get`'s default bare-value shape is unchanged, and
  `config set`/`unset` still edit only the local file.
