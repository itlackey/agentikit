### Added

- **`akm health`'s `task-fail-rate` advisory names the dominant command-task
  failure reason (#943).** Evidence now always includes
  `agentFailureReasonCounts`, a breakdown of `detail.reason` values
  (`timeout`, `non_zero_exit`, `spawn_failed`, …) across command-task
  failures in the window, and when the check is already `warn` and one
  reason covers at least half of those failures the message names it, e.g.
  `(timeout-dominant: 9/12 command-task failures)`. Investigating the
  reported issue found the underlying propagation was already correct on
  this branch — a command dispatch that times out, is killed, or returns a
  non-zero/`ok:false` result was already recorded `failed` with its reason,
  and `akm task run` already exited non-zero for it — so that contract is
  now pinned by a regression test instead of left implicit.
