### Added

- **`akm health`'s `task-fail-rate` advisory names the dominant command-task
  failure reason (#943).** Evidence now always carries
  `agentFailureReasonCounts`, a `detail.reason` breakdown (`timeout`,
  `non_zero_exit`, `spawn_failed`, …) across `command`-kind (agent/LLM
  dispatch) task failures in the window. When the check is already `warn`
  and one reason accounts for at least half of those failures, the message
  names it, e.g. `(timeout-dominant: 9/12 command-task failures)`, so a
  sustained timeout spike is visible from `task_history` data instead of
  grepping task logs. Investigating the reported instances found the
  underlying propagation already correct on this branch — a dispatched
  agent/command that times out, is killed, or returns a non-zero/`ok:false`
  result was already recorded as `failed` with its reason, and `akm task
  run` already exited non-zero for it — so that contract is now pinned by a
  regression test rather than left implicit.
