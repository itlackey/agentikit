### Changed

- **`akm index` commits embeddings per provider batch instead of once at the
  end of the whole run (#954).** Earlier releases buffered every generated
  vector in memory and wrote them all in a single `db.transaction()` after
  the entire embedding pass finished — an interruption partway through (a
  competing indexer collision, a killed process, any thrown provider error)
  discarded every embedding already computed, not just the ones still in
  flight. Each request batch now commits inside its own short transaction as
  it lands. A batch rejected specifically for exceeding the endpoint's
  context window (HTTP 413, or a recognised context-size error body) is
  split in half and retried instead of being skipped outright. Requests are
  now dispatched through a small bounded pool (1 in flight for a loopback
  endpoint, 2 for a remote one — not configurable; the real throughput knob
  is request size via the existing `embedding.batchSize` and
  `embedding.maxTokens`/`contextLength`, since a larger batch takes about the
  same wall time as a single one). `akm index` now prints progress every 500
  stored entries plus a final throughput line (`entries/s`, `tokens/s`).
