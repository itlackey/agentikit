### Changed

- **A rename of `embedding.model` no longer forces a full re-embed by
  itself (#955).** `akm index` used to purge and rebuild the entire vector
  index on any change to the fingerprint it derives from `embedding.model` —
  including a pure config rename that still resolves to the same underlying
  model (for example a gateway prefixing `provider/model` onto an unchanged
  server). On a mismatch, `akm index` now re-embeds a small sample of
  already-stored entries with the current config and compares the result
  against the stored vectors and, when available, the model id the endpoint
  itself reported on the last successful pass — the observed server identity
  is checked first (a config-only rename that still hits the same model
  answers with the same id), then a median cosine similarity of at least
  0.999 across the sample. When either check passes the index is kept and a
  log line reports it; otherwise the index is purged and rebuilt as before,
  with an up-front line naming why (dimension change, low similarity, or
  `--reembed`). A canary that cannot reach the endpoint leaves the existing
  vectors and fingerprint untouched and reports failure so the next
  `akm index` retries, rather than destroying a working index because the
  server happened to be down. A genuine dimension change is unaffected and
  still rebuilds unconditionally.

- **A purge now writes the new fingerprint before any embedding request,
  so an interrupted rebuild resumes instead of restarting from zero
  (#955).** Previously the fingerprint was only written at the very end of a
  successful embedding pass, so an interruption partway through a
  fingerprint-triggered rebuild left the old fingerprint in place — the next
  `akm index` saw the same mismatch and purged again, discarding whatever
  had already been re-embedded. The new fingerprint (and the observed
  identity) are now written in the same transaction as the purge, before any
  vectors are requested; a restart then sees a matching fingerprint and only
  re-embeds the entries still missing a vector.

### Added

- **`akm index --reembed` forces a full re-embed (#955).** Bypasses the
  compatibility check above entirely and purges + regenerates every stored
  embedding, for the rare case where the check's verdict should not be
  trusted. A targeted post-write embedding pass (after `akm remember`,
  `akm improve`, etc.) never forces a rebuild on its own.
