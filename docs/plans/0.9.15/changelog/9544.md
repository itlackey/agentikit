### Fixed

- **`akm index`'s embedding requests carry the store-resolved `secret://` credential (#953).** A field report against a gateway that tags every request by its `Authorization` header found `akm index` sending embedding requests with none, despite `embedding.apiKey` being set to a `secret://` reference — auth was not yet enforced there, so the requests succeeded silently instead of failing loudly. Every path that reaches `RemoteEmbedder` — plain `akm index`, `akm index`'s `extends`-inherited config with adapter detection persisting mid-run (#945), the CLI as a real child process, `akm bundle update`'s post-commit embedding pass, and the `akm remember` write path's targeted re-embed — was audited and reproduced against a mock endpoint recording the `Authorization` header of every request; none reproduced a keyless request against the current code, and `mutateConfig`'s returned config (the full effective config, never the pruned on-disk write body) is now documented explicitly on `ConfigMutationResult` so a future config-flow change cannot drop `apiKey` unnoticed. A new contract test pins every `RemoteEmbedder` construction site in `src/` to pass its config through by reference rather than a rebuilt object literal, so a future edit that reintroduces the gap fails the build instead of a field host.
