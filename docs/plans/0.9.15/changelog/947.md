### Added

- **`akm improve --dry-run` (or its new `--plan` alias) reports the resolved process -> engine -> model routing before anything runs (#947).** `plan.processes` is a new field, one row per improve process (`reflect`, `distill`, `consolidate`, `memoryInference`, `graphExtraction`, `extract`, `validation`, `triage`, `proactiveMaintenance`) plus a `triage.judgment` row when configured: `enabled`, the resolved `engine`/`model` for llm-backed processes, this process's own lowering `notices`, an `unavailable: {configKey, reason}` when the engine or its credential could not be resolved, and — for reflect/distill/consolidate — `eligibleRefs`, the count of this run's effective refs the process would act on. None of this is new resolution: `resolveImprovePlan` already computes it, dispatch-free, before every invocation (dry or live); this only projects it into the result. Changing `processes.consolidate.engine` and running `--plan` shows the new engine immediately, with `plan.dispatch` staying `false` — no LLM calls are made. `--strategy` overrides are honored for free, unlike `akm health`'s `active-improve-strategy` check, which still reads the configured default strategy (`defaults.improveStrategy`) and reports no model. `--plan` is a zero-logic alias for `--dry-run` — it sets the same internal flag and does not add a network reachability probe; pair with `akm health --probe` to check whether a named engine actually answers.
