### Fixed

- **Reflect no longer treats feedback lines as verified facts, and a leaked content-truncation notice defers the proposal instead of shipping silently (#952).** A harness run against akm's own reflect prompt (`reflect-llm-framed-contract.md`, `reflect-llm-schema-contract.md`) on two model quants showed the model inventing whole new sections — fabricated incident dates, ports, disk layouts — whenever a feedback line asserted a claim the source asset never made. `buildReflectPrompt` now precedes non-empty feedback with an explicit caveat: it is a signal to investigate, not a fact to insert; missing information gets a `TODO: verify …` placeholder instead of an invented answer. Separately, a model over the content cap sometimes echoed the `... [truncated — focus on the visible portion]` notice verbatim into its rewrite; `sanitizeReflectPayload` now detects a leaked marker in the response and defers the proposal for human review (`reflect-truncation-leak`), the same way an unsafe body-size ratio is deferred today. As a second layer, `proposal accept` (and drain promotion) now REJECTS any `reflect`-sourced proposal whose body still contains the truncation marker, whatever path it reached the queue by — a truncated body silently overwriting a full asset is data loss, so unlike this file's other reflect-quality checks the new validator blocks instead of only warning. Re-run reflect on the ref to clear it. `createProposal`'s mint-time structural gate for `lesson`/`task`/`workflow` refs now runs canonical-structure validation only, not the full quality-validator list, so a `lessons/…` (or `task`/`workflow`) reflect proposal that leaks the marker is still minted and deferred like any other ref instead of being rejected outright at creation.

### Changed

- **The direct-LLM reflect path sizes its asset-content budget from the target engine's `contextLength` instead of a flat 12,000-character cap (#952).** The flat cap only exists to keep the prompt under OS `ARG_MAX` when it is passed as CLI argv to an agent or SDK runner; the direct-LLM HTTP path never touches argv. Agent and SDK runners are unaffected. Configure `engines.<name>.contextLength` to raise the budget for a given engine; unconfigured engines keep today's effective ~12,000-character behavior.
